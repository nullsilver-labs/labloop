# labloop

A repo template for **agent-driven research**: a human writes the research plan, an
AI agent (Claude Code, Pi, or any AGENTS.md-aware agent) runs the experiments, keeps
the lab notebook, and leaves enough of a paper trail that — if the results are good —
you can write a publication from the artifacts alone.

This is the generalization of a workflow that ran a multi-day ML research program, 
end-to-end, managed by Claude Fable 5: pre-registered experiments, GO/NO-GO gates, 
per-run logs, and session-to-session handoffs, with the human only steering.

## How to use it

1. **Copy this repo** (or use it as a GitHub template) and rename it after your project.
2. **Write `PLAN.md`** — your research ideas, hypotheses, and goals. This is the one
   file the human must write. A skeleton with prompts is provided.
3. **Edit `CONSTRAINTS.md`** (optional but recommended) — time limits per run, budget,
   scientific constraints ("keep the LLM frozen"), directions that are off-limits,
   and what the agent must ask you before doing.
4. **Generate `HW.md`** — run `scripts/hwprobe.sh` (the agent will do this on first
   session if you don't).
5. **Launch your agent** in the repo root with a kickoff prompt like:

   > Read AGENTS.md and follow it. This is session 1: read PLAN.md, CONSTRAINTS.md
   > and HW.md, write RESEARCH_NOTES.md with your analysis of the plan, propose the
   > first experiments as specs in experiments/specs/, and stop for my review before
   > running anything expensive.

6. **On later sessions**, just say: *"Read AGENTS.md and RESUME.md, continue."*

## What the agent maintains (and where to look)

| Artifact | What it tells you |
|---|---|
| `RESUME.md` | Current state: what just happened, what's running, what's next. Read this first. |
| `experiments/LEDGER.md` | Every experiment ever attempted: status, verdict, where its logs are. |
| `experiments/specs/` | Pre-registered spec per experiment: hypothesis, metric, GO/NO-GO gate. |
| `logs/<exp_id>/<run>/` | Per-run: exact config, raw metrics (`results.jsonl`), summary with verdict. |
| `RESEARCH_NOTES.md` | The running lab notebook: theory, predictions, surprises, literature. |
| `decisions/` | ADRs: why a direction was taken or dropped, metric definitions, gate changes. |
| `paper/CLAIMS.md` | Claim → evidence map. If results are good, this is the paper's skeleton. |

## The contract in one paragraph

The human owns `PLAN.md` and `CONSTRAINTS.md`; the agent owns everything else but may
not change a pre-registered gate without an ADR, may not delete failed runs, and must
leave `RESUME.md` accurate at the end of every session. Negative results are results.

## Repo layout

```
PLAN.md            # human-curated: research ideas, hypotheses, goals   (HUMAN writes)
CONSTRAINTS.md     # human-curated: budgets, limits, hard rules         (HUMAN writes)
HW.md              # hardware inventory, generated by scripts/hwprobe.sh
AGENTS.md          # the agent's operating manual (single source of truth)
CLAUDE.md          # pointer to AGENTS.md for Claude Code
RESUME.md          # session state, updated at end of every agent session
RESEARCH_NOTES.md  # running lab notebook
experiments/       # LEDGER.md + specs/ + experiment code
logs/              # one dir per experiment, one subdir per run (committed, sans checkpoints)
decisions/         # ADRs
paper/             # CLAIMS.md + eventual draft
scripts/           # hwprobe.sh and project scripts
templates/         # experiment-spec, run-summary, ADR templates
tools/             # explogger.py — the run-dir logging contract, as code
```
